# Frontend

[Запуск всего проекта](../README.md) · [API](../docs/api.md)

React + TypeScript + Vite. Код разделён на `src/app`, `pages`, `components`, `api`, `types`, `styles`.

## Интерфейс

Используются `@mantine/core` и `@mantine/hooks` версии **8.3.18**. Общая тема находится в `src/app/theme.ts`: светлый фон, графитовый текст и кнопки, синий акцент, горизонтальная навигация и квадратное меню аккаунта. Мобильное меню поддерживает Escape, закрытие по внешнему клику и возврат фокуса. Рабочее пространство реализует выбранный макет «Ваш опыт. Для новой роли.»: исходное резюме слева, полный текст вакансии справа, одна основная кнопка создания версии.

[Mantine UI](https://ui.mantine.dev/) — источник примеров композиции интерфейсов под MIT. Готовые шаблоны оттуда не копировались: страницы собраны из компонентов Mantine. Лицензии библиотек поставляются в npm-пакетах. React/ReactDOM 19.3.1 и Vite 6.4.4 в lockfile сохранены без обновления.

## Запуск

Из `frontend`, с Node.js 22:

```powershell
npm ci
npm run dev
```

Vite проксирует `/auth` на `http://localhost:8001`, `/resumes`, `/vacancies` и `/adaptations` на `http://localhost:8002`. Адреса задаются через `AUTH_API_URL` и `RESUME_API_URL`. В Docker Compose используются `http://auth:8000` и `http://resume:8000`. Токены передаются только в заголовке Authorization своего API.

В Compose `node_modules` хранится в отдельном томе. Если после изменения зависимостей контейнер сообщает, что пакет не найден, обновите содержимое тома из lockfile и перезапустите frontend:

```powershell
docker compose exec -T frontend npm ci
docker compose restart frontend
```

## Маршруты

| Адрес | Страница |
| --- | --- |
| `/` | Публичный стартовый экран; для вошедшего пользователя — рабочее пространство |
| `/login`, `/register` | Вход и регистрация |
| `/workspace` | Выбор оригинала, текст вакансии и создание адаптации |
| `/my-versions`, `/my-versions/:id` | Версии текущей вкладки и сохранённый результат по ID |
| `/my-resumes`, `/add-resume` | Свои резюме, скачивание и загрузка PDF/DOCX |
| `/my-vacancies`, `/add-vacancy` | Свои вакансии и создание полным текстом |
| `/my-vacancies/:id` | Полный текст вакансии |
| `/profile` | Текущий пользователь |
| `/users`, `/users/:id` | Список и карточка пользователя, только сотрудники |

Кроме главной, входа и регистрации, страницы требуют подтверждённой сессии. Неизвестный адрес показывает 404. UI-пути не пересекаются с API. History API поддерживает back/forward; Vite обслуживает прямое открытие вложенных страниц. При отдельной публикации `dist` сервер должен возвращать `index.html` для UI-маршрутов и отдельно проксировать API.

Пункт «Пользователи» создаётся только при `status === 'authenticated'` и `user.is_staff === true`. Источник роли — ответ `/auth/me`. Для остальных пользователей прямые ссылки, история и возврат после входа показывают 403 до монтирования страниц пользователей и не вызывают их API. Во время проверки сессии меню и данные сотрудников не показываются. Новый ответ `/auth/me` обновляет роль; более старые параллельные ответы не восстанавливают её. Серверный 403 убирает ранее загруженные список/карточку без refresh или logout. Поведение ошибок остальных ресурсов сохранено.

## Поведение

Используются публичные `POST /auth/register`, `/auth/login`, `/auth/refresh`; `GET /auth/me`, `/auth/users`, `/auth/users/:id`; `POST/GET /resumes`, `GET /resumes/:id`; `POST/GET /vacancies`, `GET /vacancies/:id`; `POST /adaptations`, `GET /adaptations/:id`.

Рабочее пространство сохраняет вакансию полным текстом, затем создаёт адаптацию для выбранного исходного резюме. Для уже сохранённой вакансии используется её ID. Результат опрашивается каждые две секунды до `done` или `failed`; опрос отменяется при уходе со страницы. `done` с замечаниями Critic отображает текст и замечания, техническая ошибка предлагает новую попытку для сохранённой вакансии. Копирование текста имеет fallback с выделением содержимого.

У API нет списка адаптаций. «Мои версии» показывает только версии, созданные или открытые в текущей вкладке для текущего пользователя. После перезагрузки список очищается, но результат остаётся в БД и доступен по прямой ссылке. Успешный ответ создания сохраняется в этом списке и при уходе со страницы во время запроса. Смена аккаунта и явный выход очищают локальные ссылки и черновики.

Сессия хранится в `sessionStorage` и проверяется через `/auth/me`. Конкурентные 401 разделяют один refresh; исходный запрос повторяется максимум один раз. Неудачный refresh, включая серверный 500, завершает сессию. Запоздавшие ответы после выхода или смены аккаунта игнорируются. POST после сетевых ошибок и 5xx автоматически не повторяется: интерфейс предлагает сначала проверить список.

Загрузка резюме принимает пустой ответ 201. Из Location извлекается только проверенный относительный путь; запросов к переданному сервером origin нет. Скачивание использует авторизованный fetch, Blob, имя из Content-Disposition и освобождение object URL. Название в списке берётся из последнего сегмента file_url; внутренний адрес и embedding не отображаются.

Текст вакансии выводится как текст с сохранением переносов строк. Черновик, выбранный оригинал и файл сохраняются только в памяти вкладки для того же пользователя. Загрузка оригинала из рабочего пространства возвращает к вакансии и выбирает новый файл. Явный выход, смена аккаунта или перезагрузка страницы очищают черновики. Редактирование и удаление ресурсов не реализованы в текущем публичном API. Вместо вымышленного текстового предпросмотра DOCX показываются данные исходного файла и скачивание оригинала.

## Проверки

```powershell
npm run build
npm run lint
npm test
npm run test:browser
git diff --check
```

`npm test` проверяет HTTP-контракты с подменой fetch: конкурентные и запоздавшие 401, сбои refresh, logout/смену аккаунта, запрет повторов POST после неопределённого результата, пустой 201, Blob/имя файла/освобождение URL и разрешённые маршруты возврата.

`npm run test:browser` использует установленный Google Chrome, запускает Vite на `127.0.0.1:5178` (или использует уже запущенный там сервер) и проверяет 1440×900, 390×844 и 360×800. Ответы API подменяются Playwright; fixtures разделяют anonymous/nonstaff/staff. Проверяются регистрация, вход, PDF/DOCX с побайтовым сравнением скачанного файла, полный текст вакансий, профиль/пользователи, вложенные страницы, история, ошибки, черновики и истёкшая сессия. Сценарии адаптации покрывают polling, замечания Critic, техническую ошибку, неопределённый результат POST, сохранение задачи после ухода со страницы и возврат к вакансии после загрузки оригинала. Проверки прав считают вызовы API пользователей, включая ноль вызовов для закрытых URL, ожидание `/me`, отзыв роли, поздние ответы и 403 после успешной загрузки. Скриншоты всех экранов и состояний сохраняются в `test-results/visual-*`. Это проверки фронтенда, а не интеграция с backend.

При редизайне отдельно выполнен авторизованный прогон через браузер с настоящими auth/resume/worker, PostgreSQL, Redis, MinIO и gpt-4.1-mini в изолированном тестовом окружении. Одно вымышленное DOCX-резюме загрузили через интерфейс и получили две сохранённые версии под разные вакансии; проверены копирование, неизменность байтов оригинала и отсутствие приписанных навыков во второй версии. Рабочие аккаунты и документы в этом прогоне не использовались. Состояния ошибок, отклонение Critic и права сотрудников дополнительно проверяются браузерными тестами с подставными API.

В текущей Windows-песочнице обычные lint/build/test работают без изменения Vite config. Playwright не может писать в системный TEMP; для браузерного прогона временные файлы размещаются внутри проекта:

```powershell
New-Item -ItemType Directory -Force .test-build/tmp | Out-Null
$env:TEMP = Join-Path (Get-Location) '.test-build/tmp'
$env:TMP = $env:TEMP
npm run test:browser
```

# Frontend

React + TypeScript + Vite. Код разделён на `src/app`, `pages`, `components`, `api`, `types`, `styles`.

## Интерфейс

Используются `@mantine/core` и `@mantine/hooks` версии **8.3.18**. Подключение CSS и MantineProvider основано на [официальной инструкции Mantine 8 для Vite](https://v8.mantine.dev/guides/vite/). Компоненты AppShell, Drawer, NavLink, Paper, формы, кнопки и сообщения оформлены общей темой в `src/app/theme.ts`. Desktop использует графитовую навигацию 240px; мобильное меню поддерживает Escape, закрытие по внешнему клику и возврат фокуса. Главная остаётся пустой.

[Mantine UI](https://ui.mantine.dev/) — источник примеров композиции интерфейсов под MIT. Готовые шаблоны оттуда не копировались: страницы собраны из компонентов Mantine. Лицензии библиотек поставляются в npm-пакетах. React/ReactDOM 19.3.1 и Vite 6.4.4 в lockfile сохранены без обновления.

## Запуск

Из `frontend`, с Node.js 22:

```powershell
npm ci
npm run dev
```

Vite проксирует `/auth` на `http://localhost:8001`, `/resumes` и `/vacancies` на `http://localhost:8002`. Адреса задаются через `AUTH_API_URL` и `RESUME_API_URL`. В существующем Docker Compose используются `http://auth:8000` и `http://resume:8000`; сети и Dockerfile сохранены. Токены передаются только в заголовке Authorization своего API.

## Маршруты

| Адрес | Страница |
| --- | --- |
| `/` | Пустая публичная главная |
| `/login`, `/register` | Вход и регистрация |
| `/my-resumes`, `/add-resume` | Свои резюме, скачивание и загрузка PDF/DOCX |
| `/my-vacancies`, `/add-vacancy` | Свои вакансии и создание полным текстом |
| `/my-vacancies/:id` | Полный текст вакансии |
| `/profile` | Текущий пользователь |
| `/users`, `/users/:id` | Список и карточка пользователя, только сотрудники |

Кроме главной, входа и регистрации, страницы требуют подтверждённой сессии. Неизвестный адрес показывает 404. UI-пути не пересекаются с API. History API поддерживает back/forward; Vite обслуживает прямое открытие вложенных страниц. При отдельной публикации `dist` сервер должен возвращать `index.html` для UI-маршрутов и отдельно проксировать API.

Пункт «Пользователи» создаётся только при `status === 'authenticated'` и `user.is_staff === true`. Источник роли — ответ `/auth/me`. Для остальных пользователей прямые ссылки, история и возврат после входа показывают 403 до монтирования страниц пользователей и не вызывают их API. Во время проверки сессии меню и данные сотрудников не показываются. Новый ответ `/auth/me` обновляет роль; более старые параллельные ответы не восстанавливают её. Серверный 403 убирает ранее загруженные список/карточку без refresh или logout. Поведение ошибок остальных ресурсов сохранено.

## Поведение

Используются публичные `POST /auth/register`, `/auth/login`, `/auth/refresh`; `GET /auth/me`, `/auth/users`, `/auth/users/:id`; `POST/GET /resumes`, `GET /resumes/:id`; `POST/GET /vacancies`, `GET /vacancies/:id`.

Сессия хранится в `sessionStorage` и проверяется через `/auth/me`. Конкурентные 401 разделяют один refresh; исходный запрос повторяется максимум один раз. Неудачный refresh, включая серверный 500, завершает сессию. Запоздавшие ответы после выхода или смены аккаунта игнорируются. POST после сетевых ошибок и 5xx автоматически не повторяется: интерфейс предлагает сначала проверить список.

Загрузка резюме принимает пустой ответ 201. Из Location извлекается только проверенный относительный путь; запросов к переданному сервером origin нет. Скачивание использует авторизованный fetch, Blob, имя из Content-Disposition и освобождение object URL. Название в списке берётся из последнего сегмента file_url; внутренний адрес и embedding не отображаются.

Текст вакансии выводится как текст с сохранением переносов строк. Черновик и выбранный файл сохраняются только в памяти вкладки для того же пользователя при ошибках и повторном входе. Явный выход, смена аккаунта или перезагрузка страницы очищают черновики. Редактирование, удаление, runs и результаты генерации не реализованы в текущем публичном API.

## Проверки

```powershell
npm run build
npm run lint
npm test
npm run test:browser
git diff --check
```

`npm test` проверяет HTTP-контракты с подменой fetch: конкурентные и запоздавшие 401, сбои refresh, logout/смену аккаунта, запрет повторов POST после неопределённого результата, пустой 201, Blob/имя файла/освобождение URL и разрешённые маршруты возврата.

`npm run test:browser` использует установленный Google Chrome, запускает Vite на `127.0.0.1:5178` (или использует уже запущенный там сервер) и проверяет 1440×900, 390×844 и 360×800. Ответы API подменяются Playwright; fixtures разделяют anonymous/nonstaff/staff. Проверяются регистрация, вход, PDF/DOCX с побайтовым сравнением скачанного файла, полный текст вакансий, профиль/пользователи, вложенные страницы, история, ошибки, черновики и истёкшая сессия. Проверки прав считают вызовы API пользователей, включая ноль вызовов для закрытых URL, ожидание `/me`, отзыв роли, поздние ответы и 403 после успешной загрузки. Скриншоты всех экранов и состояний сохраняются в `test-results/visual-*`. Это проверки фронтенда, а не интеграция с backend.

Для интеграционной приёмки нужны работающие auth/resume, БД и MinIO: повторить сценарии на отдельной тестовой учётной записи без перехвата API, включая доступ к документам другого пользователя. При редизайне проверены только живые неавторизованные GET `/auth/me` на localhost:8001 и `/resumes` на localhost:8002: оба вернули 401. Авторизованный live-прогон не выполнялся, реальные аккаунты и документы не изменялись.

В текущей Windows-песочнице обычные lint/build/test работают без изменения Vite config. Playwright не может писать в системный TEMP; для браузерного прогона временные файлы размещаются внутри проекта:

```powershell
New-Item -ItemType Directory -Force .test-build/tmp | Out-Null
$env:TEMP = Join-Path (Get-Location) '.test-build/tmp'
$env:TMP = $env:TEMP
npm run test:browser
```
